# 阿里中北线图文攻略

打开 `tibet-guide.html`，或在当前目录运行 `python3 -m http.server 8766 --bind 127.0.0.1` 后访问 `http://127.0.0.1:8766/tibet-guide.html`。

本页只采用方案 A，不含交互地图、路书或动态视频；原 `amap-jsapi/` 保持不变。照片来源与天气核对时间均可在页面展开查看。两张已授权照片保存在本地，其余照片为远程引用，需要联网；离线时文字、酒店表、天气快照和曲线仍可使用。

## 内容维护

- `guide-itinerary.js`：13 天时间窗、玩法、取舍与住宿关联。
- `guide-weather.js`：墨迹带明确日期的天气快照优先；未覆盖日期可用 `guide-weather-trends.js` 中经浏览器核验的 MSN 30 天远期趋势。只填可核验日期，缺失使用 `null`；日最低不等于 07:00—24:00 小时最低。
- `guide-weather-evidence.json`：2026-09-25 浏览器核对的墨迹页面证据与日期范围。19 个有效天气页面提供 31 个唯一地点/日期记录，映射 36 个行程节点；圣象天门使用本次重新核验的 1 个 MSN 30 天趋势节点。页面与 Markdown 均逐节点记录来源及核对时间。
- `guide-weather-trends.js`：MSN 各地点定位、逐日趋势、复查步骤和原始日历证据；不是历史平均值。09.25 仅刷新当前使用的圣象天门 10.05（10℃／0℃），其天气文字与风速未取得，不沿用旧值；未使用的历史记录保留各自核对日期。曲线用虚线空心点，概览、每日行程及来源卡均标注远期趋势。
- `guide-research.js`：票务、预约、政策及其来源。
- `guide-drone.js`：独立的逐日、逐点无人机核验数据；UOM 页面颜色与景区/场地管理分列记录，并注明观察时间、定位精度、结论和来源。搜索匹配点的颜色不代表实际起飞点、整个景区或完整飞行范围已确认；白区不自动等同法定管制区或可飞区。
- `guide-drone-evidence.js`：仅保存 UOM 页面实见证据，在 `guide-drone.js` 前加载。`window.TIBET_DRONE_EVIDENCE` 包含 `legend` 与 `observations`。图例的 `colorsVerified: true` 表示页面色块已实际观察，需同时记录 `observedAt`、`note`、`sources`；`verified: true` 另指法律含义已完整核验，二者不混同。单点以 `rowId` 关联行程，记录 `status`（`blue` / `white` / `mixed` / `unverified`）、`queryText`、`matchedResult`、`zoom`、`observedAt`、`note` 和来源 `sources`，可附截图路径 `evidence`。`unverified` 用于未成功定位或读取颜色的查询，时间显示为尝试日期，不计入已核验数量。只有色块已观察且单点必填证据完整、地图级别至少 9 级时才计为“UOM 颜色已核验”；法律含义尚不完整不妨碍展示真实颜色，但不会据此生成适飞许可。缺失、模糊、加载中的白底或仅搜到名称均保持待核验。原始查询词、匹配结果、级别、观察时间、说明在页面及生成 Markdown 中同步展示。
- `guide-media.js`、`guide-hotel-media.js`、`guide-extra-media.js`：实景照片、作者、许可与酒店详情链接。明确要求授权的来源只显示原文入口。
- 酒店卡片按入住日期包含主酒店及备选，分别展示外观和每个已订房型；双床/标间在大床前。房型图片须有来源房型名或房型 ID 的对应证据，不能仅凭床数相似就替代；未核实的图片明确留空。表格中的“外观与房型图片”可跳转到相应卡片。
- 2026-09-19 图片覆盖：18 家酒店的外观、23 种已订房型；尼玛五龙宾馆缺少可确认的同名同址来源，外观和供氧舒适标准间均待用户提供链接或照片。已逐图检查卧室/门头画面，不只依赖图库分类；使用同一图片的 1280px CDN 版本，保留原始地址及来源证据。
- `guide.js` / `guide.css`：页面渲染和响应式样式。不加载地图 API，也不发起天气 API 请求。

酒店值由 `build-guide.mjs` 从原 `amap-jsapi/app.js` 精确复制到生成的 `guide-base.js`；海拔沿用原近似数据，新攻略按确认后的塔尔钦、尼玛住宿衔接调整。该命令也会生成同步的 `tibet-guide.md`。不要手工编辑生成文件。

```sh
node build-guide.mjs
node test-guide.mjs
GUIDE_DATA_ONLY=1 node test-guide.mjs
node test-weather-render.mjs
node test-drone-render.mjs
```

测试需要本地服务器、Playwright 与 Chrome。默认使用 Codex 已提供的 Playwright 包和 macOS Chrome；可通过 `GUIDE_PLAYWRIGHT_PATH`、`GUIDE_CHROME_PATH`、`GUIDE_TEST_URL` 指定。测试覆盖 360/390/768/1440px、数据完整性、天气合并、无人机逐日逐点覆盖及空域/场地分列、打印排版和本地文件打开，截图保存到系统临时目录。

`test-weather-render.mjs` 是不联网、不启动浏览器的离线页面模板回归，检查真实天气、无趋势、部分缺失和全缺失四种输入；不检查视觉排版或远程图片。2026-09-25 更新后应运行两目录的构建、数据断言与模板回归。模板区分本次核验与旧趋势，未核实的天气文字和风力不会显示为新数据。Git 提交与推送按用户当次授权执行。

`test-drone-render.mjs` 同样是离线模板回归，覆盖真实证据载入、原始蓝区/白区/混合颜色、证据不全、图例未观察和查询文本转义；测试夹具不会写入真实证据文件，不核查真实地图颜色或视觉排版。`observedAt` 可只记真实观察日期（如 `2026-09-24`），无精确时间证据时不得补造时分。
